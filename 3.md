# `rootfs.Unpack` walkthrough

This explains `pkg/rootfs/unpack.go` (plus its two platform-specific
companions) - the function `PullRootFS` calls to turn a pulled `v1.Image` into
a real directory tree on disk, ready for `mkfs.ext4 -d` to pack (see `1.md`).

## Signature and job

```go
func Unpack(ctx context.Context, img ggcrv1.Image, root string) error
```

Give it an image handle and a directory, and when it returns successfully,
`root` contains that image's complete, merged filesystem - every layer applied
in order, every deletion resolved, every file at the path it belongs at. No
OCI layer structure survives; what's on disk afterward is indistinguishable
from what you'd get by running the image as a container and looking at its
rootfs.

## Step by step

### 1. Make sure `root` exists

```go
os.MkdirAll(root, 0o755)
```

Nothing clever here - `root` is normally a fresh scratch directory handed to
`Unpack` by `store.Stage()` (see `2.md`), but `MkdirAll` makes the function
correct even if called against a directory that doesn't exist yet.

### 2. Flatten the layers with `mutate.Extract`

```go
rc := mutate.Extract(img)
defer rc.Close()
```

This is the piece that does the actual "merge all layers, resolve whiteouts"
work - and it's not our code. `mutate.Extract`, from `go-containerregistry`,
walks `img`'s layers **newest-first** and streams out a single tar that
already has every `.wh.<name>` deletion and `.wh..wh..opq` opaque-directory
marker resolved - the returned stream contains exactly the final merged state,
with no whiteout markers left in it at all. (See `pkg/oci`'s commit history
for why we moved to this instead of applying each layer to disk ourselves via
containerd's `archive.Apply` - short version: this does the same job, is
already a dependency, and let us drop a much heavier one.)

Because `mutate.Extract` returns an `io.ReadCloser` backed by a goroutine
writing into a pipe, closing `rc` (via the `defer`) is also how an early
return - including a context cancellation - unwinds that goroutine: once the
pipe's reader side is closed, the writer's next write fails and the goroutine
exits.

### 3. Walk the merged tar and extract each entry

```go
tr := tar.NewReader(rc)
for {
	if err := ctx.Err(); err != nil { return err }
	hdr, err := tr.Next()
	...
	name := cleanTarPath(hdr.Name)
	target, err := secureJoin(root, name)
	p, err := writeEntry(root, target, hdr, tr)
	if p != nil { pending = append(pending, *p) }
}
```

For every entry in the already-flattened stream:

- `cleanTarPath` strips any leading `/` and lexically resolves `.`/`..` in the
  entry's name, **without** clamping a `..` that climbs above the root - so an
  escaping path stays recognizable as escaping instead of silently becoming
  harmless.
- `secureJoin` then rejects that escape outright. This is redundant in the
  strict sense - `mutate.Extract` already rejects unsafe paths (and unsafe
  symlink/hardlink targets) before they ever reach this stream - but it's
  cheap, and defense-in-depth against a corrupted stream or a future library
  behavior change costs nothing here.
- `writeEntry` (below) does the actual filesystem work for that one entry.

A hardlink entry whose target isn't on disk *yet* doesn't fail outright - it's
queued into `pending` and retried once the whole stream has been drained (step
4). This matters because of the same newest-first order mentioned above: a
hardlink added in a newer layer can point at a file that was only ever created
in an older layer, which - in the merged stream - appears *after* the
hardlink that references it.

### 4. Resolve any pending hardlinks

```go
for _, p := range pending {
	os.Link(p.linkTarget, p.target)
}
```

By this point every entry in the stream has been written, so every hardlink
target that's going to exist, does. If one still doesn't, that's a genuinely
malformed image, not an ordering artifact - and `Unpack` returns an error
rather than silently dropping the link.

## What `writeEntry` does, per tar entry type

```go
func writeEntry(root, target string, hdr *tar.Header, tr *tar.Reader) (*pendingLink, error)
```

It first `os.MkdirAll`s `target`'s parent directory (tar streams don't
guarantee a directory entry precedes every file inside it), then dispatches on
`hdr.Typeflag`:

- **`TypeDir`** - `ensureDir` makes sure `target` is a directory (removing
  whatever's there first if a file occupied that path in an earlier,
  now-superseded layer), then `os.Chmod`s it to the header's mode.
- **`TypeReg`** - removes anything already at `target`, then
  `os.OpenFile`s with `O_CREATE|O_TRUNC|O_WRONLY` at the header's mode and
  copies exactly `hdr.Size` bytes from the tar reader.
- **`TypeSymlink`** - removes anything at `target`, then `os.Symlink`s
  `hdr.Linkname` as-is (a symlink's target isn't resolved during extraction -
  only later, inside whatever actually reads it).
- **`TypeLink`** (hardlink) - resolves `hdr.Linkname` through `secureJoin` too
  (a hardlink target is just as capable of escaping `root` as the entry's own
  name), then `os.Link`s it. If the target doesn't exist yet, returns a
  `*pendingLink` instead of failing (see step 4 above).
- **`TypeChar` / `TypeBlock` / `TypeFifo`** - delegates to `mknodEntry`, a
  platform-specific function (below).
- Anything else is an error - there's no tar entry type this doesn't know how
  to handle that should legitimately appear in a Linux container image.

After a successful, non-pending write, it calls `applyPlatformMetadata` to
restore ownership and extended attributes.

## Why two of these are platform-specific

`mknodEntry` and `applyPlatformMetadata` live in `unpack_linux.go` and
`unpack_other.go`, split by `//go:build linux` / `//go:build !linux`:

- **`unpack_linux.go`**: `unix.Mknod` actually creates the device/FIFO node;
  `unix.Lchown`/`unix.Lsetxattr` restore the tar header's UID/GID and any
  `SCHILY.xattr.*` PAX records. Both are **best-effort** - errors are
  discarded - because this runtime only needs to run as root in production
  anyway (it already needs raw KVM/TAP access to launch Firecracker VMs), so a
  permission failure here would only ever happen during local, non-root
  development, and shouldn't abort an otherwise-successful unpack.
- **`unpack_other.go`**: `mknodEntry` returns an explicit "not supported on
  GOOS=…" error instead of silently doing nothing, since a missing device node
  is a real correctness gap, not a cosmetic one. `applyPlatformMetadata` is a
  harmless no-op, since without `Mknod` even working there's nothing
  meaningful to `chown`/`setxattr` differently.

This split is what lets `pkg/rootfs`'s tests run on macOS during development
(no device nodes in the test fixtures) while the Linux build path - the one
that actually matters, since Firecracker itself is Linux/KVM-only - gets the
real syscalls.

## What `Unpack` deliberately does *not* do

- **No OCI whiteout logic of its own.** That's entirely `mutate.Extract`'s job;
  `writeEntry` never looks for a `.wh.` prefix because, by the time it sees an
  entry, there isn't one left.
- **No per-layer digest verification.** The previous implementation (using
  containerd's `archive.Apply` layer-by-layer) hashed each layer's
  uncompressed bytes against `config.RootFS.DiffIDs[i]`. Once extraction
  became "read one already-merged stream," there was no longer a clean
  per-layer boundary to check against - and `go-containerregistry` already
  verifies each layer's *compressed* bytes against the manifest digest on the
  way in, which comes from the same already-authenticated source as the
  config. The config/DiffID check was a secondary safety net; this was a
  deliberate trade of that redundancy for dropping the entire `containerd`
  dependency tree.
- **No ext4 packing.** `Unpack` only produces a directory. Turning that
  directory into the actual mountable image is `pkg/ext4`'s job, called
  separately by `PullRootFS` right after `Unpack` returns (see `1.md`).
