# `PullRootFS` walkthrough

This explains `pkg/backbone/fs.go`'s `PullRootFS` method and the supporting
packages it calls into. It's the implementation of the `RootFSService.PullRootFS`
RPC defined in `pkg/api/runtime/v1/api.proto`.

## What it's for

This project is a Firecracker-based sandbox runtime. To boot a Firecracker VM you
need a root filesystem attached as a **block device** (see `RootFSMount` in
`api.proto`, modeled on Firecracker's `Drive`). An OCI image, on the other hand, is
a stack of compressed tar layers plus a JSON config. `PullRootFS` is the bridge
between the two: given an image reference, it produces an ext4 image file on disk
that Firecracker can mount directly, and it caches that result so repeated pulls of
the same content are cheap.

The method is on `*RootFS`, a struct with two fields:

```go
type RootFS struct {
	v1.UnimplementedRootFSServiceServer
	store  *store.Store   // pkg/backbone/store - local metadata + file layout
	packer ext4.Packer    // pkg/ext4 - turns a directory into an ext4 image
}
```

`store` and `packer` are the two seams that make the rest of the method testable
(see `pkg/backbone/fs_test.go`, which injects a fake packer and a real but
temp-dir-backed store).

## Step by step

### 1. Validate input

```go
spec := req.GetSpec()
image := spec.GetImage()
if image == "" {
	return nil, status.Error(codes.InvalidArgument, "spec.image must be set")
}
```

`RootFSSpec.image` is the only required field - it's a reference like
`docker.io/library/alpine:3.19`, a bare digest, or (per the proto's own comment)
possibly a template name/URI, though only the OCI-registry path is implemented.

### 2. Pull the image (metadata only)

```go
img, err := oci.PullImage(ctx, image, authOption(req.GetAuth()))
```

`oci.PullImage` (`pkg/oci/pull.go`) wraps `crane.Pull`. It resolves the reference,
fetches the manifest, and - if the reference points at a multi-arch index -
resolves it to the child manifest matching **this host's actual CPU
architecture** (`runtime.GOARCH`), not `go-containerregistry`'s hardcoded `amd64`
default. That distinction matters here specifically because Firecracker needs the
guest architecture to match the host's; there's no cross-arch emulation.

Crucially, nothing has been downloaded yet except the manifest (and, for an
index, the child manifest). `img` is a lazy `v1.Image` handle - its config and
layer blobs are fetched only when something actually reads them.

`authOption` maps the request's optional `AuthConfig` (username/password,
pre-encoded `auth`, identity/registry tokens) onto a `crane.Option`, falling back
to the default keychain (anonymous + any local `~/.docker/config.json`) when no
credentials were supplied.

Errors here are split into two buckets:
- `oci.ErrInvalidReference` (bad input, e.g. an unparseable string) →
  `codes.InvalidArgument`.
- Anything else (registry 401/403/404, network failure) → `pullError`, which
  inspects the error chain for a `*transport.Error` and maps its HTTP status to
  `Unauthenticated` / `PermissionDenied` / `NotFound`, defaulting to `Internal`.

### 3. Compute the digest and derive reference strings

```go
digest, err := img.Digest()
digestStr := digest.String()          // "sha256:<hex>"
repoTag, repoDigest := repoRefs(image, digestStr)
```

The manifest digest (not the tag) is the **stable identifier** used everywhere
downstream - it's what `RootfsRef` in the response contains, and it's the key
the local store is organized around. `repoRefs` re-parses `image` locally (no
network call - `oci.PullImage` already validated it) to recover, if it was a tag
reference, the fully-qualified tag string (e.g.
`index.docker.io/library/alpine:3.19`), and always computes the fully-qualified
digest reference (`.../alpine@sha256:...`). Both are just bookkeeping for later
`ListRootFS`/`RootFSStatus` lookups by tag.

### 4. Cache-hit short-circuit

```go
if _, ok, err := r.store.Lookup(digestStr); err != nil {
	...
} else if ok {
	r.store.AddRef(digestStr, repoTag, repoDigest)
	return &v1.PullRootFSResponse{RootfsRef: digestStr}, nil
}
```

This is the idempotency story. If this exact content (by digest) has already
been pulled and packed, nothing is re-downloaded, re-unpacked, or re-packed -
the call just records that this *reference* (possibly a new tag pointing at
already-known content) also resolves to that digest, via
`store.AddRef` merging it into the existing entry's `RepoTags`/`RepoDigests`.

### 5. Stage, unpack, measure, pack (the expensive path)

Only reached on a true cache miss.

```go
extractDir, tmpImage, cleanup, err := r.store.Stage()
defer cleanup()

rootfs.Unpack(ctx, img, extractDir)
```

`store.Stage()` (`pkg/backbone/store/store.go`) allocates a fresh scratch
directory under `<root>/tmp/`, split into an `extract/` subdirectory and a path
for the in-progress image file. The `defer cleanup()` guarantees that scratch
space is removed on every exit path - success or failure.

`rootfs.Unpack` (`pkg/rootfs/unpack.go`) does the real work of turning layered
OCI content into a flat directory tree:

1. It calls `mutate.Extract(img)` (from `go-containerregistry`), which walks the
   image's layers **newest-first** and produces a single already-merged tar
   stream, correctly resolving OCI whiteouts (`.wh.<name>` deletes a file from a
   lower layer; `.wh..wh..opq` marks a directory opaque, hiding everything
   beneath it from lower layers).
2. It reads that merged stream and materializes it onto `extractDir` with a
   plain tar extractor (no whiteout logic needed here - that's already done) -
   handling regular files, directories, symlinks, hardlinks, and (on Linux)
   device nodes/xattrs/ownership via `unix.Mknod`/`Lchown`/`Lsetxattr`.
3. Hardlinks whose target hasn't been written yet (possible because
   `mutate.Extract` emits layers newest-first) are queued and retried once the
   whole stream has been read.

### 6. Size the ext4 image and pack it

```go
totalBytes, entryCount, err := ext4.MeasureTree(extractDir)
sizeBytes := ext4.EstimateImageSize(totalBytes, ext4.DefaultSizeOptions)
inodeCount := ext4.EstimateInodeCount(entryCount, ext4.DefaultSizeOptions)

r.packer.Pack(ctx, extractDir, tmpImage, sizeBytes, inodeCount)
```

`ext4.MeasureTree` walks the extracted directory once to get total file bytes
and entry count. `EstimateImageSize` adds 20% slack (minimum 64 MiB) on top of
the measured size, rounded to a 4096-byte block. `EstimateInodeCount` sizes the
inode budget directly from the entry count (not a bytes-per-inode guess), so a
tree with many small files doesn't run out of inodes before it runs out of
space.

`r.packer` (normally `ext4.MkfsExt4Packer`) then shells out to
`mkfs.ext4 -F -d <extractDir> -N <inodeCount> <tmpImage> <sizeBytes>K`. The `-d`
flag populates the filesystem directly from the directory at creation time, so
no loop-mount and no root privileges are needed to build the image (root *is*
still needed at extraction time to `chown` files to arbitrary UIDs, same as any
real container runtime).

### 7. Commit into the store

```go
fi, err := os.Stat(tmpImage)

entry := store.Entry{
	Digest: digestStr, Size: uint64(fi.Size()),
	SpecImage: image, SpecAnnotations: spec.GetAnnotations(),
	RepoTags: ..., RepoDigests: ...,
}
r.store.Commit(entry, tmpImage)
```

`store.Commit` atomically `os.Rename`s the packed image from scratch space into
`<root>/images/sha256-<hex>.ext4`, then writes a JSON metadata sidecar
(`sha256-<hex>.json`) next to it - merging `RepoTags`/`RepoDigests` into an
existing entry if one somehow already exists (defensive; shouldn't happen given
the step-4 check, but makes concurrent pulls of the same new digest safe too).
Nothing under `<root>/images/` is ever partially written: the rename is the only
thing that makes an entry visible.

### 8. Return

```go
return &v1.PullRootFSResponse{RootfsRef: digestStr}, nil
```

The digest is the handle callers use in every later call -
`RootFSStatus`/`RemoveRootFS` accept it directly via `store.Resolve`, which
tries it as a bare digest first and falls back to matching it against stored
tags/digests.

## Why it's structured this way

- **Digest-keyed, not tag-keyed.** Tags are mutable and ambiguous (`:latest` on
  two different registries points at different content); content digests are
  stable. The store is organized entirely around digests, with tags layered on
  top as discoverable aliases.
- **Stage-then-rename, never in-place.** Every expensive step (unpack, measure,
  pack) happens in scratch space that's invisible to readers until the final
  `Commit`. A crash or error at any point leaves the store exactly as it was
  before the call started.
- **Narrow interfaces for testability.** `ext4.Packer` is an interface
  specifically so `fs_test.go` can swap in a fake that just touches a file,
  without needing `mkfs.ext4`/root privileges to unit-test the orchestration
  logic. The real `mkfs.ext4` path is exercised separately via
  `make test-integration` (a Linux container, since `mkfs.ext4` doesn't exist on
  macOS).
